# 0003. 分层混合知识库架构 (Layered Hybrid Knowledge Base)

## Context
系统需要提供近10年的国考、各省省考、事业单位联考真题及官方采分标准，以及权威时政资料（篇幅达数十兆）；同时，考生需要上传自己的私有学习资料、个性化讲义与复习笔记。
如果将全量真题打包进前端并在初次加载时全部灌入浏览器 IndexedDB，会导致首屏下载体积过大、初始化卡顿且存在浏览器存储配额限制；如果将考生的私有资料上传至后端持久化存储，则违反了系统“零服务端个人数据留存”的最高安全原则。

## Decision
我们决定采用**分层混合知识库架构**：
1. **预置公共知识库（Default Public KB）**：
   - 托管于服务端只读静态目录（`server/data/default_kb/`），包含近10年真题文本、材料与官方采分细则；
   - 服务端启动时仅以只读索引形式提供元数据查询与按需单篇拉取接口（`GET /api/kb/exams`）；在批改时作为客观真实采分底稿（Ground Truth Anchor），杜绝大模型打分幻觉。
2. **私有自建知识库（Private User KB）**：
   - 考生自行上传的私密讲义、时政文件与个人笔记，100% 存储于浏览器本地 IndexedDB；
   - 仅在浏览器端提供本地快速全文检索，支持鼠标划词【一键转存个人记忆库】。
3. **统一聚合视图**：
   - 前端将“🏛️ 官方真题与标准采分底稿”与“📂 我的私有学习资料”聚合呈现，实现统一检索。

## Consequences
- **优势**：前端首屏秒级轻量加载；近10年海量真题与官方采分标准高效共享且不挤占浏览器配额；考生的私有笔记资料物理级隔离在本地，安全可控。
- **代价**：服务端需维护静态真题的 JSON/Markdown 目录与只读元数据索引。
