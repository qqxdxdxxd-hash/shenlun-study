# 0004. 纯客户端自持密钥与严格 BYOK 模型接入机制 (Strict BYOK)

## Context
申论智能批改与 Skill 提炼高度依赖大模型算力。若由服务端集中配置 API Key 并向所有用户分发，不仅带来巨额 Token 账单与滥用风险，而且用户无法使用自己最熟悉或最先进的模型（如各类第三方网关、私有推理端点）。此外，若服务端保存用户密钥，存在凭证泄露风险。

## Decision
我们决定采用**纯客户端自持密钥（Strict BYOK - Bring Your Own Key）机制**：
1. **服务端零密钥存储**：服务端环境完全不配置、不维护、不持久化任何默认或共享的 API Key。
2. **前端本地托管凭证**：用户在网页前端设置页输入自己的 `API Key`、`Base URL`（兼容 OpenAI 规范）以及 `Model ID`，数据 100% 保存在浏览器本地（LocalStorage/IndexedDB）。
3. **透传中转与即刻销毁**：前端在请求批改、Skill 提炼或微练习验证时，将凭证携带于 HTTP 请求中；后端仅作为格式组装与转发代理，大模型调用完成后即刻随当前请求生命周期彻底销毁，内存不留痕。

## Consequences
- **优势**：服务端运营成本为零，无 Token 账单风险；任何第三方部署均无需担心密钥窃取；用户拥有最高自由度，可任意切换火山方舟、DeepSeek、Qwen、Claude 等模型。
- **代价**：新用户初次使用必须具备一个 OpenAI 兼容的大模型 API Key 才能完成批改体验。
