# 0001. 前后端分离与客户端纯本地存储（无状态后端）

## Context
申论备考过程中的考生作答、错题病灶与自建记忆库高度私密。传统 Web 应用将用户数据存储在服务端集中式数据库（如 MySQL/PostgreSQL），不仅带来多租户数据泄露风险与隐私顾虑，还增加了服务端的运维与存储成本。

## Decision
我们决定采用**前后端分离架构**，其中：
1. **客户端（浏览器）**：作为唯一的“数据存储与检索引擎”，利用 IndexedDB 完整持久化保存考生的作答记录、批改报告、个人名言对策库（SM-2 艾宾浩斯调度）及跨试卷认知病灶图谱，并提供 JSON 全量导出备份。
2. **服务端（FastAPI）**：作为纯粹的“无状态算力后端与 Skill 挂载器”，仅负责解析本地 `skills/` 目录下的名师评分标准，编排大模型 Prompt 并计算色谱标注跨距。服务端**不设任何数据库，实行零数据留存（Zero-Retention）**，计算完成立即向前端推流并释放内存。

## Consequences
- **优势**：考生数据资产 100% 物理留存于本地设备，杜绝泄露风险；服务端无状态轻量化，极易水平扩展或单机部署。
- **代价**：跨设备同步需要依赖考生手动导入导出 JSON 备份（后续阶段可通过用户自建 WebDAV / GitHub Gist 扩展实现私有云同步）。
