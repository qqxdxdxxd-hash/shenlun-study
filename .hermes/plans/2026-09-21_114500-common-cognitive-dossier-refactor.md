# 通用化认知病灶图谱重构方案 (Skill-Neutral Cognitive Defect Dossier Plan)

## Goal
构建与具体名师流派完全解耦、分题型独立统计、量纲数学严谨、支持下钻溯源与动态克服的“通用认知病灶图谱 (Universal Cognitive Defect Dossier)”。

---

## 1. 当前现状与已识别的六大硬伤 (Current Context & Problem Statement)

在现有实现中，【认知病灶图谱】（`web/index.html` 的 `#tab-dossier`、`web/js/app.js` 的 `recordDossierDefects` / `renderDossierList`）存在以下根本性缺陷：

1. **题型混为一谈（最根本缺陷）**：
   - 申论大作文（议论文）、公文题（贯彻执行）、单一题（概括归纳）的阅卷逻辑截然不同：单一题需要高频摘抄材料采分原词，大作文严禁抄袭；公文题考核五要素公文格式，大作文考核议论骨架。
   - 当前代码中，入参虽有 `qType`，但在写入 IndexedDB `dossier` 表时完全未保存 `questionType` 字段；
   - 所有题型的作答篇数与扣分点被放入同一个全局分母（`submissions.length`）做除法，导致单一题摘抄采分词被误判为“材料依附抄袭红线”，大作文的骨架缺陷被大量单一题作答稀释。
2. **写死具体流派偏称（违背 Skill 中立与自定义扩展原则）**：
   - 诊断文本与作答页警报强行写死“大五段”、“1+3 骨架”等特定流派教研术语；
   - 若考生使用提炼工坊自建了“四段式”、“策论八股”或“案例思辨型”私有 Skill，病灶图谱仍强推“大五段”，造成严重的认知混乱与流派冲突。
3. **分子分母量纲不一致（数学穿帮，触发率可能 > 100%）**：
   - 当前代码：`colloquialErrors` 统计的是“单句瑕疵总条数”，而分母 `total` 是“答卷总篇数”；
   - 若考生在一篇大作文中出现 3 处口语大白话，`colloquialRate` 计算结果为 `(3 / 1) * 100 = 300%`，百分比爆表穿帮。
4. **病灶成为不可交互的“死数据”（无法下钻溯源 Drill-Down）**：
   - 界面仅展示干瘪的百分比进度条，点击无法展开查看：“究竟是在哪一天的哪篇作答中犯的错？被扣分的具体原句是什么？当时考官的具体扣分评语是什么？”
   - 无法一键跳转回原卷复盘当时的完整色谱标注。
5. **全量静态累加，缺乏滑动窗口与趋势感知**：
   - 无论作答多少篇，早期初学时的犯错记录永远死死咬住考生的统计分母；
   - 无法反映“最近 3~5 篇作答”的真实动态水平，无法展现克服病灶后的上升曲线。
6. **生命周期断裂（`cleared: 0` 字段成摆设）**：
   - 数据库 Schema 虽设计了 `cleared` 标记，但业务逻辑中没有任何将病灶从未克服（Active）流转为已切除（Remediated）的机制；
   - 作答页置顶红色警报永久常驻，导致考生视觉脱敏（Alert Fatigue）。

## 2. 架构设计与通用元维度模型 (Architecture & Common Taxonomy)

### 2.1 五大通用元维度 (Universal Meta-Dimensions)
摆脱任何特定名师技巧与具体骨架限制，锚定公考官方阅卷最本质的 5 个通用元能力维度，任何 Skill（官方内置或考生自建）均自动映射入此模型：

| 通用元维度 Key | 维度名称 (Common Label) | 考核核心本质 (Core Capability) | 题型映射行为 (Question-Type Mapping) |
| :--- | :--- | :--- | :--- |
| `DIM_THEME` | **审题立意与核心论点** | 是否切准题目任务、总论点/核心观点是否明确、有无跑偏或泛化。 | - 大作文：切题度、总论点醒目度与主旨高度；<br>- 公文题：发文事由明确度、工作目标对齐；<br>- 单一题：作答对象与审题范围锁定。 |
| `DIM_STRUCTURE` | **结构层次与逻辑骨架** | 段落布局是否匀称、层次是否清晰（总分/并列/递进）、公文或归纳格式是否完整。 | - 大作文：各分论点布局对仗度、首尾呼应；<br>- 公文题：法定/事务性格式五要素完整度；<br>- 单一题：前置大词分类、归纳逻辑清晰度。 |
| `DIM_ANALYSIS` | **论证深度与要点提炼** | 是深入分析还是机械罗列流水账、材料采分要点是否遗漏或割裂。 | - 大作文：事例后有无因果制度深析（拒流水账）；<br>- 公文/单一题：材料采分要点覆盖率、归纳提炼准度。 |
| `DIM_EXPRESSION` | **政务规范与语言洗练** | 杜绝口语大白话与随意表达，规范使用政务公文动宾搭配与概括大词。 | - 全题型通用：口语大白话检测、非规范句式、口水话过渡词。 |
| `DIM_COMPLIANCE` | **客观合规与字数红线** | 遵守考场物理规程与格式红线。 | - 大作文：材料连续抄袭率（>20%红线）；<br>- 全题型：字数严重不足/超限、标点与书名号硬伤。 |

### 2.2 题型隔离与滑动窗口计算模型
1. **题型独立分流**：
   - 筛选维度：`all` (全部总览), `essay` (大作文), `official_doc` (公文题), `single_question` (单一题)；
   - 分母：对应题型的总作答篇数 $N_{\text{type}}$。
2. **正确量纲核算（双指标并存）**：
   - **作答触碰率 (Occurrence Rate)**：$\frac{\text{触发该缺陷的独立作答篇数}}{\text{该题型总作答篇数}} \times 100\%$（绝对区间 0%~100%）；
   - **单篇发生频次 (Defect Density)**：$\frac{\text{该缺陷在历史中的总出现次数}}{\text{该题型总作答篇数}}$（如“平均每篇 1.8 处”）。
3. **滑动窗口状态定级（基于最近 5 篇对应题型作答）**：
   - **一级顽固病灶 (Level 1 Critical)**：最近 3 篇中触碰 $\ge 2$ 次，或触碰严重合规红线；
   - **二级偶发瑕疵 (Level 2 Warning)**：最近 5 篇中触碰 1 次；
   - **已克服/良好 (Remediated / Healthy)**：最近 3 篇连续未触碰，或历史无记录。

### 2.3 下钻与动态自反性联动
- **病灶卡片下钻 (Drill-Down)**：点击任一维度卡片，原地展开“历史扣分原卷切片”，展示当次试卷标题、提交日期、被扣分原句 (`quoteText`) 及考官判语，提供按钮【🔍 查看原卷完整色谱】；
- **自反性前置警报**：作答页面根据当前选中的题型，只拉取该题型当前的“一级顽固病灶”，并使用通用提示语（如：“本次为大作文作答，历史检测到你在此题型常有【论证缺乏深度、语言口语化】病灶，请重点加强因果制度剖析并使用政务大词！”），彻底清除“大五段”写死措辞。

## 3. 实施步骤与分步任务 (Step-by-Step Implementation Tasks)

### Task 1: 升级客户端 IndexedDB Schema (v3) 与数据升级迁移
- **文件**：`web/js/db.js`
- **操作**：
  1. 将数据库版本提升至 3；
  2. 为 `dossier` 对象仓库添加复合索引：`questionType`、`dimensionKey`、`severity`、`cleared`；
  3. 完善字段结构，确保新存入记录均包含 `questionType`, `examTitle`, `dimensionKey`, `evidenceQuote`, `clearedAt`。
- **验证命令**：
  在浏览器控制台执行 `window.clientDB.getAll('dossier')` 确认 Store 升级成功且复合索引生效。

### Task 2: 重构病灶采样与记录函数 `recordDossierDefects`
- **文件**：`web/js/app.js`
- **操作**：
  1. 接收 `(subId, qType, examTitle, userText, res)`；
  2. 根据 5 大通用元维度分类萃取：
     - `DIM_COMPLIANCE`：
       - 若 `qType === 'essay'` 且 `(res.copy_redline_exceeded || res.copy_ratio > 0.18)`，记录议论文材料过度依附；
       - 若标题格式硬伤（如书名号硬伤），记录合规缺陷；
       - 若字数严重不足，记录字数硬伤；
     - `DIM_EXPRESSION`：
       - 提取 `res.chroma_spans` 中 `type === 'colloquial_flaw'` 的全部切片，记录为语言表达大白话病灶；
     - `DIM_ANALYSIS`：
       - 提取 `type === 'story_narrative_leak'`（案例流水账）或扣分项中关于论证深度不足的评语；
       - 若单一题中采分点覆盖率较低，记录采分要点遗漏；
     - `DIM_STRUCTURE`：
       - 若打分中结构与逻辑维度扣分较多（低于满分 60%），记录结构逻辑残缺（使用通用评语，不写死大五段）；
     - `DIM_THEME`：
       - 若立意与总分论点维度扣分严重，记录审题立意偏题病灶；
  3. 每条记录存储包含 `questionType` 与 `examTitle`，确保单次提交中同一维度的瑕疵可精确聚合或展开。
- **验证**：执行一次本地测试批改，检查 IndexedDB `dossier` 表中成功落入带 `questionType` 的新记录。

### Task 3: 实现量纲严谨的病灶统计与滑动窗口分析引擎
- **文件**：`web/js/app.js` (新增 `DossierAnalytics` 模块逻辑)
- **操作**：
  1. 编写通用统计分析函数 `calculateDossierMetrics(dossiers, submissions, filterType = 'all')`：
     - 依据 `filterType` 过滤 `submissions`（获取分母总数 $N_{\text{type}}$ 及最近 5 篇作答 ID 集合）；
     - 聚合计算 5 大元维度的：
       - `distinctCount`（触碰该维度的独立答卷数）；
       - `rate` = `Math.round((distinctCount / N_type) * 100)%`（绝不超过 100%）；
       - `totalInstances`（总瑕疵点数）；
       - `density` = `(totalInstances / N_type).toFixed(1)`（平均每篇瑕疵频次）；
       - `recentHits`（在最近 5 篇作答中的触碰次数）；
       - `status`（`一级顽固病灶` / `二级关注` / `良好安全`）；
  2. 实现手动标记克服与撤销流转函数 `toggleDefectClearance(dossierId)`；
  3. 实现自动销号检测逻辑（若某维度在最近 3 篇中为 0 触碰，且历史曾有病灶，打上 `auto_remediated` 标签）。

### Task 4: 重构 `#tab-dossier` UI 界面与交互下钻
- **文件**：`web/index.html` 与 `web/styles/main.css`
- **操作**：
  1. 在 `#tab-dossier` 顶部增加题型切换 Tab 按钮组：
     - `[全部总览 (0)]`、`[大作文 (0)]`、`[公文题 (0)]`、`[单一题 (0)]`；
  2. 重构病灶卡片渲染：
     - 展示维度标签、状态徽章、触碰率、单篇平均瑕疵频次、最近 5 篇趋势点阵；
     - 增加展开按钮 `[展开历史扣分原卷 (N条)]`；
     - 展开区域展示每篇答卷的标题、时间、被标注原文切片 (`quoteText`) 与考官扣分诊断，提供快捷操作 `[查看当次色谱报告]`。
- **验证**：点击不同题型 Tab，卡片列表平滑切换，分母与频次数字精准对应对应题型，卡片可折叠展开。

### Task 5: 重构作答页面自反性警报与题型联动 (`renderDossierWarningOnReviewPage`)
- **文件**：`web/js/app.js`
- **操作**：
  1. 作答页面题型下拉框（`#question-type-select`）绑定 `change` 事件；
  2. 题型切换时，动态调用 `renderDossierWarningOnReviewPage(currentQType)`；
  3. 仅提取当前题型下处于 `一级顽固病灶` 状态的通用元维度；
  4. 警报文案通用化生成，例如：
     - 大作文：“根据你最近大作文作答，系统检测到你存在【材料抄袭依赖过重、语言口语化】顽固病灶，本次作答请独立提炼观点，杜绝照抄材料，多用政务大词！”；
     - 公文题：“根据你最近公文作答，系统检测到你存在【公文格式要素不全】病灶，请严格核对标题、主送、正文、落款五要素！”；
     - 单一题：“根据你最近单一题作答，系统检测到你存在【核心采分点遗漏】病灶，请充分挖掘材料关键词并分类提炼！”。

## 4. 自动化测试与验证 (Tests & Validation)

1. **自动化统计逻辑测试**：
   - 编写浏览器端/Node 单元测试 `test_dossier_analytics.js`：
     - 模拟 3 篇单一题作答（无抄袭，含采分词）+ 2 篇大作文（1 篇含 3 个口语词，1 篇超字数）；

     - 验证单一题的材料摘抄不会触发大作文的 `ERR_COPY_OVER_20`；

   - 启动 `start.bat`，访问 `http://127.0.0.1:8789/`；
   - 分别提交一篇大作文与一篇单一题批改；
   - 进入【认知病灶图谱】Tab：
     - 检查题型分流按钮是否正常切换；
     - 检查病灶卡片点击展开后是否能看到刚才答卷的句子原词；
     - 检查作答页在切换“公文题”时，不再出现任何“大五段”字样。

## 5. 风险与权衡 (Risks, Tradeoffs & Open Questions)

1. **历史旧数据迁移风险**：
   - 现有 IndexedDB 中已经存在的旧 `dossier` 数据没有 `questionType` 字段；
   - **对策**：在 `db.js` 版本升级 hook 中执行数据平滑迁移，通过 `submissionId` 反查对应的 `submissions` 记录补齐 `questionType`，若无法关联则归入 `essay` 或标记为 `unclassified`，保证平滑升级不丢数据。
2. **LLM 输出维度映射的健壮性**：
   - 不同的 Skill 在 Prompt 中返回的扣分项描述可能略有差异；
   - **对策**：基于 `models.py` 中已有的固定色谱类别（`colloquial_flaw`, `story_narrative_leak`, `main_thesis`）与四大打分雷达维度做确定性映射，保证提炼规则的 100% 稳定可靠。
